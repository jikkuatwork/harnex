# Harnex 0.19.0 — local-only verification

Date: 2026-10-20. Local install only (owner decision 2026-10-18); no RubyGems
publication, tag or push. Live checks used Pi 1.3.0 (`foundry-zyt/gpt-6.1-sol`
by default) in scratch repositories with worktree lanes, owned by this Claude
Code session and by Claude Code subagents it spawned.

## Changes

#85 (Pi/GPT workers as native tools for Claude Code): `harnex ask`;
`final_message` / `end_sha` / `commits` / `turn_commits` / `model` on every turn
result; `run --wait-done`; `--owner-tag`; `watch --owner --match` and
`--until-idle`; `--once` prints every ready event; per-turn owner-record
history (no lost turns, settle order); `running_commands` in status and stall
lines; `send` fails fast on an exited lane; `send --stall-after`; compound
durations; `--context-section "## Task"`; `harnex agents-guide claude`. Full
list: `CHANGELOG.md`.

## Evidence

- Full Ruby suite at the release source: **959 runs, 4,532 assertions**, zero
  failures/errors, three opt-in live-provider skips.
- Installed: `harnex --version` → `0.19.0 (2026-10-20)`; 68 shipped
  `lib/`, `guides/` and `bin/` files match the source byte for byte;
  `harnex agents-guide claude` is served from the gem.
- **Stress round 1 (installed 0.18.0, three Claude subagents in parallel):**
  S1 drove three lanes through slow (`sleep 150`), stall (`sleep 400`, stopped
  on `stalled`) and quick paths plus a `--wait-done` 124 → `--after-seq`
  resume; S2/S3 ran as two subagents sharing one owner id. Every lane's own
  events arrived, classes and stop/stall/resume paths were right, and git
  attribution was correct. Found: lost turns when two turns ended between
  polls (bug), no reply text anywhere (subagents scraped `harnex logs`), no
  lane scope for subagents sharing an owner (only `CLAUDE_CODE_CHILD_SESSION=1`
  distinguishes them), stale backlog on a fresh cursor, `send` to an exited
  lane waiting out its timeout, `wait` calling a stopped session running.
  All fixed here.
- **Stress round 2 (checkout CLI; subagents given only `agents-guide claude`):**
  R1 got two GPT second opinions with `harnex ask` (default model and
  `gpt-6-sol`; `gpt-6-luna` hit a provider rate limit) whose analysis matched
  the code and surfaced a real follow-up counting race (fixed). R2 ran three
  `--owner-tag` lanes in parallel, sent a busy follow-up (`follow_up`,
  `{sent: 1, pending: 0}`, acted on), a second turn, merged all branches
  itself (43 runs green); it saw no other subagent's lanes. R3 delegated from
  a 45 KB brief (Task section only, `context_sha256` recorded) in one call,
  got the reply matching git, and walked the forced 124 → `resume` path.
- **Pre-release live re-check (checkout CLI):** `ask --timeout 8m30s` answered
  in 10s with the model on stderr and added no dispatch rows to the repo;
  two `--context-section "## Task"` lanes under one `--until-idle` call
  returned both results (with `turn_commits`, `model`, `final_message`) after
  46s.
- **Installed-CLI smoke:** `harnex ask` from a worktree answered correctly in
  10s.

  `CLOCK_MONOTONIC`, which did not advance, so `--timeout` did not bound wall
  time across the pause. Environment caveat, not addressed.
- Usage errors still exit 2, the same code as "proof rejected" (documented:
  they print no JSON).
