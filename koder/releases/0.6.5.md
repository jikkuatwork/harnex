## Long-run stress dispatch (`quality-audit`)

Single ~9-minute dispatch tasked with deep code-quality + doc-freshness
audit of harnex itself. Designed to load the JSON-RPC transport with
sustained reads + reasoning + structured artefact writes.

| metric | value |
|---|---|
| `duration_s` | 533 |
| `exit` | success |
| `input_tokens` | 2,224,841 |
| `output_tokens` | 25,584 |
| `reasoning_tokens` | 14,158 |
| `cached_tokens` | 1,474,560 |
| `disconnections` | 17 |
| `stalls` | 0 |
| `force_resumes` | 0 |
| `commits` | 0 (worker wrote a report file outside the repo) |

Live `harnex status` `auto_disconnects` counter climbed `0 → 3 → 7 →
12 → 16` over the run. **Every disconnection was auto-recovered by
the JSON-RPC client; the worker's task survived intact and exited via
`task_complete`.** This is the single best end-to-end validation of
the #27 reconnect path under realistic load and the #33 token-capture
under high churn.

The audit report itself (`/tmp/harnex-quality-report.md`, 27 KB,
229 lines) found two classes of follow-up work:

- **Code-side concurrency / hardening** in `Session`,
  `Adapters::CodexAppServer`, `ApiServer`, and `Inbox` —
  unsynchronized state, no JSON-RPC request timeout, untracked HTTP
  handler threads, `Inbox#@messages` unbounded growth, `inbox.rb`
  ArgumentError race between `deliver_now` and `delivery_loop`.
- **Doc staleness** in `CLAUDE.md`, `README.md`, `TECHNICAL.md`, and
  `docs/{codex-appserver,events,dispatch-telemetry}.md` — stale test
  count (174 vs 396), legacy item types, omitted shipped flags, and
  PTY-only transport claims that no longer match code.

Both are summarized in `koder/STATE.md`'s handoff. Neither
has been filed as a tracked issue yet.

## What this verification did NOT cover

- Cross-platform behavior (macOS, BSD). Linux only.
- Long-running PTY adapter (Claude Code, opencode, etc.) — JSON-RPC
  Codex was the focus.
- Multi-session orchestration / chain workflows.
- `harnex events --snapshot` / Layer 4 event stream consumption (the
  `--watch` babysitter was not exercised here).
- `--legacy-pty` Codex path. The compatibility surface is unchanged
  by 0.6.5, but it was not re-smoke-tested.
