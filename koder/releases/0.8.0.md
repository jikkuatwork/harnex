# harnex 0.8.0 - release verification

- **Released:** 2026-08-02
- **Commit:** `e7f9f04`
- **Tag:** `v0.8.0`
- **Headline changes:** Release of #62 live-run observability: durable
  `dispatch_start` rows at registration, live `status`/`history`/`wait`
  visibility with `source: live|registry|dispatch_start` labelling and
  `degraded: true` when the live API is unreachable, the documented
  `wait --until done` exit-code contract (0/1/2/3/124), and the
  duplicate-dispatch guard (`--attempt-kind retry` requires
  `--parent-dispatch-id`; `--allow-live-parent` overrides). Minor bump for
  the two behavior changes: `wait --until done` no longer passes the child's
  exit code through, and retry dispatches require a parent dispatch id.
- **Verified against:** locally-installed `harnex 0.8.0 (2026-08-02)` via
  `gem install harnex`.

## Known display artifact (pre-existing, not 0.8.0)

`.harnex/dispatch.jsonl` in this repo contains nine 2026-05-era rows in the
old `{meta, predicted, actual}` telemetry schema (written by harnex ~0.7.2).
`harnex history` does not recognize them and renders a blank row. Cosmetic
only; the file is valid JSONL and current-schema rows render correctly. A
fix would be to skip rows without a top-level `id`/`record_type` in the
history renderer. Not filed as an issue (awaiting user direction).

## Long-run telemetry

No multi-hour or overnight dispatch was executed for this release. Verification
used the full deterministic suite (which includes the Q096 acceptance test
`test/integration/live_run_observability_test.rb`) plus installed-binary smokes
of the new guard, wait-contract, history, and doctor surfaces.

## What this verification did NOT cover

- A real mid-run `harnex status`/`history`/`wait` observation of a live
  dispatched worker from a second shell (the suite covers this with
  deterministic fixtures; no live two-session smoke was run).
- `--allow-live-parent` override path and the `review` exemption on a live
  parent (suite-covered only).
- Real Codex, Pi, or Claude model turns; long-running production queue
  workloads; recovery after proof failure.
- Live PTY strict-mode prompt transitions in tmux.
- #57's remaining outcome classes and failure-budget rollup; #42 / plan 30
  live recovery/fallback producers; #63/#64 (filed, not started).
- Cross-platform behavior (Linux-only validation).
