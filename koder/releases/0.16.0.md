# Harnex 0.16.0 — local-only verification

Date: 2026-10-18. Source: `6602912e209c62f211ac710e33586b6588bfe34d`.

Owner decision (2026-10-18): Harnex is installed locally and is not published
to RubyGems. No Git push, tag, RubyGems publication or public artifact transfer
occurred. Live checks dispatched short Pi/Codex preflight sessions in throwaway
scratch repositories only; no product repository was touched, and the two
unrelated live sessions on the machine (`pi-impl-63`, `pi-q158-r4`) were left
alone.

## Changes

- **#68** `harnex run --final-gate '<cmd>'` (or meta `final_gates`): receipts
  gain `validation.commands_had_failures` (whole history) and
  `validation.final_gates`; declared gates decide `validation.status` by each
  gate's last observed exit. Diagnostics only; acceptance is unchanged.
- **#57** Process outcome classes (`boot_failure`, `permission_prompt`,
  `timeout`, `stopped_by_caller`, `process_failed`) refine unknown/failed
  terminals and receipt rejections of processes that never signalled
  completion. `harnex orchestration report` counts classes per attempt and per
  retry family, accepts `--queue-id`, and evaluates `--failure-budget` (exit 3
  on breach).
- **#56** `harnex preflight ADAPTER [--cwd] [--commit-check]`: one tiny real
  dispatch, JSON verdict `harnex.preflight.v1`, distinct failure classes,
  telemetry provenance; rows tagged `phase=preflight` and excluded from
  orchestration rollups by default.
- **#26** `harnex status` names sessions active in other repos when the current
  repo has none. **#49** a bare `harnex wait` notes when the session will not
  exit on its own. Status JSON gains `auto_stop`.
- Events `ts` has millisecond precision (#36/#37 follow-up). Doctor advertises
  `final_gates`, `outcome_classes` and `preflight` capabilities.
- Tracker: closed stale #04 #06 #30 #33 #34 #35 #36 #37, closed #72 (no public
  release), resolved #26 #49 #56 #57 #68.

## Evidence

- Full Ruby suite at the source above: **887 runs, 4,199 assertions**, zero
  failures/errors, three opt-in live-provider skips. Three consecutive green
  runs after isolating two pre-existing suite flakes (leaked registries in
  status tests; a detached-teardown race in the on-done smoke).
- Independent fresh-context review of the code diff found 9 defects (1 P1,
  5 P2, 3 P3), each reproduced, fixed in `e180bc8` with regression tests: the
  process classes were unreachable through real finalization (receipt path);
  start rows double-counted in rollups; spawner parents merged unrelated
  families; budget breach exit collided with usage errors; preflight could
  orphan a worker from a repo subdirectory; launch errors and timeouts were
  misattributed; `--final-gate=` was not a wrapper token; the reserved
  preflight phase failed repo phase allowlists.
- Live from the checkout: `harnex preflight pi` passed every check in 57s with
  observed usage, provider-reported cost and observed context;
  `--commit-check` passed (scratch repo advanced; caller repo untouched).
  `harnex preflight codex` failed fast (~20s) with `failure: task_failed`,
  reporting the redacted `401 invalid_api_key` from the local Codex
  configuration as the root cause.
- Installed: `harnex --version` → `0.16.0 (2026-10-18)`; all 75 installed files
  match the source byte for byte; `harnex doctor --adapter pi` ok with the new
  capabilities. The touched suites (218 runs, 1,086 assertions) pass when
  loaded from the installed gem's `lib`/`bin`.
- Installed-CLI live Pi preflight from a repo **subdirectory** passed every
  check (20.4s), left the subdirectory empty and no task files in `/tmp`; its
  row carries `phase=preflight`, `harness_version: 0.16.0`, Pi's raw command
  strings, and `final_gates.status: pass`. The `status` hint was observed live
  ("2 active sessions in other repos ...").
