# Harnex 0.18.0 — local-only verification

Date: 2026-10-20. Local install only (owner decision 2026-10-18); no RubyGems
publication, tag or push. Live checks used Pi 1.3.0 (`foundry-zyt/gpt-6.1-sol`)
in throwaway scratch repositories with sibling worktree lanes, owned by this
Claude Code session.

## Changes

- **#83** `run --context-file PATH [--context-section TEXT]`, `--meta-file`;
  `meta.context_file` / `meta.context_sha256` on the started event and both
  dispatch rows. `--tmux` hands the brief over by path.
- **#84** `watch --owner --once [--timeout DUR] [--cursor NAME]`.
- **#80** worktree lanes observed in their own Git toplevel; end row
  `root_commit_sha`.
- **#79** busy Pi sends become Pi follow-ups; expired sends exit 1 and
  timed-out sends withdraw their message (exit 124).
- **#82** `provider_capacity` outcome class (Pi retries exhausted).
- **#81** `send` reports `after_seq`; `wait --after-seq`; `send --wait-done`;
  per-turn results in events and the owner stream (`turn`, turn-relative
  `elapsed_s`, `settled_at`, `follow_ups`).

## Evidence

- Full Ruby suite at the release source: **939 runs, 4,445 assertions**, zero
  failures/errors, three opt-in live-provider skips. (Baseline before the work:
  910 runs; one known-flaky port test, `test_allocate_port_respects_requested_port`,
  failed once in a parallel run and passes alone.)
- Installed: `harnex --version` → `0.18.0 (2026-10-20)`; all 64 tracked
  `lib/`, `guides/` and `bin/` files match the source byte for byte; the new
  flags appear in the installed `--help` output.
- **Claude subagent dogfood (checkout CLI):** a general-purpose Claude Code
  subagent managed a Pi lane end to end with foreground blocking calls only
  (`--cwd` worktree, `--root` master, brief via `--context-file` +
  `--context-section "Sent verbatim"`, `--meta-file`). A send one second after
  launch went in as `delivery: follow_up` and the worker committed it in the
  same turn. `watch --owner --once --cursor` returned turn 1 (`done`,
  `completed_with_proof`) after 48s; `send --wait-done` blocked for turn 2 and
  returned `turn: 2`; `wait --after-seq` resumed correctly and kept waiting
  past the last turn; the owner stream reported turn 2 once. The dispatch row
  credited the lane HEAD as `commit_sha` and recorded the subagent's own
  master commit only as `root_commit_sha`. Its friction list drove four
  pre-release fixes: turn-relative `elapsed_s`, `settled_at`, `follow_ups`
  (proof a follow-up reached the model), `tmux_target` in `run` output, plus
  help text for `context_sha256` and shared subagent owner ids.
- **Live re-check of those fixes (checkout CLI):** busy send → `follow_up`;
  turn result `follow_ups: {sent: 1, pending: 0}` with both commits on the
  lane; nudged turn 2 reported `elapsed_s: 20` ("after 20s"); `tmux_target`
  printed (`%503`); dispatch row `commit_sha` = lane HEAD, `root_commit_sha` =
  master HEAD.
- **Installed-CLI smoke:** `harnex run pi --tmux --cwd <lane> --root <master>
  --context-file … --auto-stop` then `harnex watch --owner --once` → `done`,
  `completed_with_proof`, 37s; row `harness_version` 0.18.0, lane commit
  credited.
