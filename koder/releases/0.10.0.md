# harnex 0.10.0 - release verification

- **Released:** 2026-08-03 | 02:00 PM | IST
- **Commit:** `de7cd12`
- **Tag:** `v0.10.0`
- **Headline changes:** **breaking** — `--summary-out` removed outright (#65),
  so `.harnex/dispatch.jsonl` is the only telemetry destination and both flag
  spellings hard-error. Plus four runner reliability fixes found while
  verifying that removal (#66): concurrent registry corruption, a delivered
  send reported as failed, a corrupt registry entry crashing every session
  scan, and a closed stdout wedging the wrapped agent. Also ships #64
  harness-authored observed-state receipts, which were implemented but
  unreleased at 0.9.0.
- **Verified against:** published and locally installed
  `harnex 0.10.0 (2026-08-03)`.

## Did not cover

- **No real-agent (Codex/Claude/Pi) source or installed smoke.** Every dispatch
  in this matrix used a stub Ruby agent. 0.9.0 verified against live Codex with
  bounded evidence files; 0.10.0 did not. The `#65` telemetry-shape and `#66`
  concurrency changes are transport-agnostic, but adapter-specific regressions
  would not have been caught here.
- **No independent reviewer pass.** 0.9.0 went through bounded review cycles;
  this release was verified by the implementing session only.
- **Cross-process registry lost-update race** between a live session persisting
  its registry and the parent `harnex run` running `annotate_tmux_registry` on
  the same file. Each write is atomic and the merge is intentional, so this is
  a stale-field risk rather than corruption. Known and unaddressed.
- **`Harnex.strip_ansi` does not `scrub` invalid bytes** the way
  `Adapters::Base#normalized_screen_text` does. Its callers sit inside
  already-rescued teardown telemetry, so it degrades rather than crashing.
- **App-server stub threads in tests remain fire-and-forget.** They only read
  pipes, and the isolation net now reaps them, but they were not individually
  rewritten.
- **Four stale local `.gem` build artifacts** (`0.6.2`, `0.6.3`, `0.7.0`,
  `0.7.1`) were deleted from the working directory during this session by an
  over-broad cleanup glob. Untracked and gitignored, regenerable from tags or
  RubyGems; noted here so the loss is on the record.
