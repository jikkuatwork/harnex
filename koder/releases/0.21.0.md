# Harnex 0.21.0 — local-only verification

Date: 2026-10-22. Local install only (owner decision 2026-10-18); no RubyGems
publication, tag or push. Owner asked: "Please release locally and stress
test it". This release lets the `gpt` Claude Code subagent (#86 slice 1) run
GPT tasks longer than its 10-minute Bash cap.

## Changes

- `harnex ask --resume ID --repo ROOT [--timeout DUR] [--json]`: keeps
  waiting on an ask that timed out and prints the answer like the original
  ask (same exit codes; full answer from `final_message_path` when truncated).
- A timed-out ask names that command on stderr instead of a raw
  `harnex wait …` (which prints JSON). `--json` keeps the run's own `resume`.
- `harnex doctor` capabilities add `ask_resume`.
- Guide `06_claude` documents the resume loop.
- Outside this repo: the `gpt` agent type,
  `~/Projects/pi/.claude/agents/gpt.md` (Haiku, Bash only), linked as
  `~/.claude/agents/gpt.md`. It relays a brief through `harnex ask` and
  returns the reply verbatim.

### Stress test through the installed CLI

Eight `gpt` subagents were launched in one message from an interactive
Claude Code session (2.1.308), so up to 8 Pi lanes ran at once. Default
model `foundry-zyt/gpt-6.1-sol`.

**Passed**

- **L, long write task (11-minute command):** two relay Bash calls. The ask
  exited 124 at 9m and named `harnex ask --resume pi-ask-75f5 --repo …`. The
  relay ran exactly that command, which returned `LONG-OK` with exit 0.
  677s wall in total.
- **W1 / W2, parallel writers in separate worktrees of one repo:** commits
  `8fc62e9` (`lane-1`) and `dab0bfb` (`lane-2`) in 24s and 26s. Each branch
  holds only its own change, and both changes run.
- **R1, read-only:** correct (`0.21.0`, `ask_resume`) in 24s.
- **R3, `model: gpt-5.5`, `effort: low`:** correct adapter list in 14s.
- **F, a 4,408-byte answer:** above the 4,000-character `final_message`
  cap, so the full text came from the file. The relay returned all 1,101
  lines byte for byte. 36s.
- **E, `model: no-such-model-xyz`:** exit 1 with the provider's 404,
  reported as `GPT did not answer (exit 1): …`. The relay did not answer
  the question itself. 6s.

**Provider-limited**

- **R2, `model: gpt-6-luna`:** exit 1 after about 122s of Pi retries, from a
  token rate limit on Azure eastus2. Reported correctly.
- **R2b, the same question with `fallback: gpt-6.1-sol`:** luna was limited
  again; harnex re-asked on sol, which answered correctly (128s in total).

**Relay cost and cleanup**

- Each relay used about 12k–17k Haiku tokens, with 1 Bash call (2 for L).
- No sessions were left running (`harnex status --all` empty).

An earlier run (headless `claude -p` parent, 0.20.0 CLI) passed four lanes:
read-only, model header, shell-metacharacter fidelity and write mode.

## Known issues

- **Escaped results.** Claude Code delivers background-subagent results to
  the parent XML-escaped (`&amp;`, `&lt;`, `&gt;`). The relay's own text is
  exact, but a parent that copies the notification literally prints the
  entities. This is outside harnex.
- **Agent loading.** Agent types load at Claude Code session start; a
  session opened before the link existed cannot launch `gpt`. It appeared
  mid-session here only after the definition existed.
- **Resume timing.** After a resume, the stderr line reports only the resume
  call's wait ("answered in 128s"), not the whole ask.
- **`.harnex/dispatch.jsonl`.** A `mode: write` ask in a repo without
  `koder/` leaves an untracked `.harnex/dispatch.jsonl`. This is existing
  `run` behavior.

## Did not cover

- A real `provider_capacity` failure on a *write* ask with fallback (the
  fallback re-runs the whole brief, so a partly done write task restarts).
- More than 8 concurrent lanes; asks longer than one resume round
  (about 18 minutes or more); the 12-round relay cap.
- Host suspend during a wait (waits still use `CLOCK_MONOTONIC`).
- Pi's suggested migration to a pinned install (`curl … | sh`) was not run.
