# harnex 0.7.8 — release verification

- **Released:** 2026-06-13
- **Commit:** `72eee70`
- **Tag:** `v0.7.8`
- **Headline changes:** Native work-terminal watcher for existing visible/detached sessions. `harnex watch --id <id> --until done` wraps the existing `wait --until done` fence, exits `0` for successful work, non-zero for `task_failed` / failed terminal telemetry, `124` for wall-clock timeout, and supports optional done/fail marker files plus `--stop-on-terminal`. Documentation now distinguishes `harnex watch` from foreground `harnex run --watch` stall babysitting.
- **Verified against:** locally-installed `harnex 0.7.8 (2026-06-13)` via `gem install harnex`.

## Long-run telemetry

No multi-hour or overnight dispatch run was executed for this release. Telemetry validation focused on the native watcher command and terminal-summary fallback behavior. The installed smoke used a synthetic terminal summary row rather than launching a live agent, so no new DISPATCH row metrics, disconnection counts, or live-agent exit reason were produced by the smoke.

## What this verification did NOT cover

- Long-running unattended queue monitoring over a real multi-hour worker.
- `--stop-on-terminal` against a live harnex API server; unit coverage exercises watcher terminal classification, while installed smoke focused on terminal-summary success.
- Real `task_failed` from a live Codex/Pi dispatch in the installed smoke; unit tests cover `task_failed` preserving non-zero exit and avoiding `/status` polling.
- Pi PTY/TUI marker support (#45).
- Queue-aware telemetry contract implementation (#47).
- Codex orchestrator recovery (#42) or deployment fallback work (plan 30 Phases 3–5).
- Cross-platform behavior (Linux-only validation in this release).
