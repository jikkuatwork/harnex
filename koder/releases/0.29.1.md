# Harnex 0.29.1 — local-only verification

Date: 2026-10-23. Local install only; RubyGems and GitHub stay on 0.29.0
until the owner approves publishing. Fixes #88.

## Changes

- The runs behind lanes carry `meta.phase`: `delegate` or `ask` by
  default. Like `preflight`, these harnex-owned phases pass any repo phase
  allowlist, including one with `"policy": "reject"`.
- `harnex delegate --phase NAME` and `harnex ask --phase NAME` name a work
  phase instead. The allowlist checks it, and `reply` reuses it.
- A launch refused before the worker started leaves no lane record or
  brief. A refused `reply` restores the lane's previous state. `delegate`
  clears a record that 0.29.0 left this way, so the name can be reused.

## Evidence

- Suite: **827 runs, 4,310 assertions**, 0 failures, 1 opt-in skip. Run
  twice, once before and once after the version bump.
  - New tests in `lanes_test`, `ask_test` and `run_test` cover: lane phase
    tags, the exemption under `reject`, a refused lane leaving no record and
    freeing its name, a refused reply keeping its state, and a 0.29.0
    leftover freeing its name.
  - Four of the new lane assertions fail on the 0.29.0 code.
- Installed `0.29.1`: `harnex --version` matches, 89 files. `harnex doctor`
  → ok; integrations `claude_mcp`, `pi_mcp` and `gpt_agent` are all true.
- **Live smoke** in a scratch git repo, Pi 1.4.0 on gpt-6.1-sol. The repo's
  `.harnex/config.json` had allowlist `implement, code-review` and policy
  `reject`.
  - `delegate --name refused-88 --phase bogus`: refused before spawn, exit
    1, with the allowlist message; `harnex lanes --all` showed no record.
  - `delegate --worktree refused-88` (same name): done in 12s, 1 commit.
    Its dispatch rows were tagged `phase: delegate`.
  - `reply refused-88`: resumed and done in 12s, 2 commits in total; rows
    tagged `delegate`.
  - `ask --write`: answered in 9s; rows tagged `ask`.
  - `land refused-88`: merged 2 commits and removed the worktree and branch.
    The smoke repo and the ask lane were removed afterwards.
