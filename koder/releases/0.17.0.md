# Harnex 0.17.0 — local-only verification

Date: 2026-10-18. Source: `d53c18c60b77dcd9b5b53d5f9eecbd31f0555081`.

Local install only (owner decision 2026-10-18); no RubyGems publication, tag or
push. Live checks used short Pi dispatches in a throwaway scratch repository,
owned by this Claude Code session.

## Changes

- **#77** `harnex watch --owner [ID]`: an owner-scoped stream of compact JSON
  lines (`harnex.owner_event.v1`, with a readable `msg`). Events: `started`,
  `done`, `rejected`, `failed`, `stalled`, `stopped`, `timeout`. No
  heartbeats; it runs until killed or `--max-wait` (124), and a per-owner
  cursor delivers each result once across restarts. Built for Claude Code's
  `Monitor`.
- **Behavior change:** `harnex run` from a Claude Code Bash shell now records
  `CLAUDE_CODE_SESSION_ID` as the dispatch owner, so it writes #72 owner
  records. `PI_SESSION_ID` keeps precedence, and explicit
  `--orchestration-session-id` wins over both. The tmux hand-off runs
  `env HARNEX_OWNER_RESOLVED=1 harnex run ...` so a tmux server's stale env
  cannot claim a dispatch.
- Documented `harnex status --json` consumer fields.

## Evidence

- Full Ruby suite at the source above: **910 runs, 4,280 assertions**, zero
  failures/errors, three opt-in live-provider skips.
- Installed: `harnex --version` → `0.17.0 (2026-10-18)`; all 77 installed files
  match the source; owner-stream/run/stall/notifier suites (130 runs, 554
  assertions) pass when loaded from the installed gem's `lib`.
- Live acceptance (checkout, Claude Code `Monitor`, owner auto-detected from
  `CLAUDE_CODE_SESSION_ID`): three concurrent Pi dispatches produced exactly
  one `started` and one terminal line each (`done`, `done`, and the manually
  stopped worker) and one `stalled` line per silent session
  (`--stall-after 20s`, `clock=activity`). It also exposed that Pi settles a
  stopped turn as `failed`; the stream now classifies `failed` settlements from
  the dispatch row, and a live re-run reported `stopped` /
  `stopped_by_caller`. The restarted stream repeated none of the earlier
  results (cursor).
- Installed-CLI smoke: `Monitor` on the installed `harnex watch --owner`
  delivered `started` then `done` (`completed_with_proof`) for a Pi dispatch
  launched with the installed `harnex run` (auto-owned), and repeated none of
  the earlier results (the cursor written by the pre-release checkout runs
  carried over).
