# harnex 0.7.10 — release verification

- **Released:** 2026-07-10
- **Commit:** `b278c0c`
- **Tag:** `v0.7.10`
- **Headline changes:** `harnex run --artifact-report PATH` and `--validation-report PATH` now expose a worker-writable `harnex.artifact_report.v1` sidecar path via `HARNEX_ARTIFACT_REPORT_PATH` / `HARNEX_VALIDATION_REPORT_PATH`, ingest the report at dispatch finalization, and append compact `artifact_report`, `validation`, and `artifacts` blocks to the dispatch summary row. Missing, malformed, unsupported-schema, and oversized reports fail soft with warning telemetry.
- **Verified against:** locally-installed `harnex 0.7.10 (2026-07-10)` via `gem install harnex`.

## Long-run telemetry

No multi-hour or overnight dispatch run was executed for this release. Telemetry validation focused on short-lived sidecar ingestion and dispatch summary shape. The installed smoke used a deterministic Ruby child rather than a real Codex/Pi model turn, so no meaningful token/cost/disconnection metrics were produced.

## What this verification did NOT cover

- Long-running unattended queue runs where a worker produces sidecars over many hours.
- Real Pi/Codex model behavior writing a sidecar from a natural-language prompt; installed smoke used a deterministic Ruby child.
- Queue-aware attribution flags and reliability split from #47 beyond the validation/report sidecar slice shipped here.
- Typed artifact dashboard/UI or automatic closeout tooling.
- Security/privacy review of arbitrary sidecar contents beyond the 256 KiB cap and compact field extraction.
- Pi PTY/TUI marker support (#45).
- Codex orchestrator recovery (#42) or deployment fallback work (plan 30 Phases 3–5).
- Cross-platform behavior (Linux-only validation in this release).
