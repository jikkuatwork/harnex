# Harnex 0.30.0 — verification

Date: 2026-10-25, a local install (`gem install --local`; not published).
Resolves #89, #90, #91 and #92, filed from Holm's first nights with lanes
(Holm Queue 167).

## Changes

- **Lane names (#89).** A bare layout (`repo/.bare` plus sibling worktrees)
  is one lane namespace, keyed by the worktree on the bare repo's `HEAD`
  branch. A lane in flight (running or uncollected, or a worktree lane not
  yet landed) holds its name across every repo. A lane in another worktree
  is named after it. `delegate --worktree` refuses a `--cwd` that is already
  another worktree. The `gpt` agent takes tool arguments from header lines
  only, has a new `name:` header, and passes `cwd:` to `result`/`reply`.
- **Worktree location (#90).** `.harnex/config.json` `lanes.worktree_path`
  and `lanes.branch` templates (`{name}`, `{yyyy}`, `{mm}`, `{dd}`); `land`
  and `discard` follow each lane's recorded path and branch.
- **Worker commits (#91).** The session reads `HEAD` around each worker
  command that runs git and emits `worker_commits`. An in-place lane's
  footer counts only those and names the rest (`HEAD also moved N by
  others`).
- **Interjections (#92).** `harnex send` records its sender on the `send`
  event. Lane results list messages from anyone but the lane's owner and its
  own `reply`, and print the answers the worker gave earlier in the turn
  (`earlier_replies`) before the latest one.

## Evidence

- Suite: **841 runs, 4,443 assertions**, 0 failures, 1 opt-in skip (827
  before). Run twice: after the main change and after the earlier-reply fix
  below. New tests in `lanes_test`, `session_pi_rpc_test`, `mcp_test`,
  `config_test` and `core_test` cover the bare layout, numbering, in-flight
  refusal across repos, the nested-worktree refusal, config templates through
  `land`, worker-commit counting, interjections and earlier replies (with
  Pi's per-call `turn_start` events), sender identity, and the MCP `name`.
- Installed `0.30.0`: `harnex --version` matches, 89 files, installed
  `lib/` identical to the repo's; `harnex doctor` → ok, integrations
  `claude_mcp`, `pi_mcp` and `gpt_agent` all true.
- **Live smoke** (Pi 1.4.0, gpt-6.1-sol) in a scratch holm-style layout
  (`proj/.bare`, `proj/master`, three sibling worktrees), run from `master`:
  - #89: three `delegate --no-wait --cwd ../night-X` with the same brief
    became `pi-night-a`, `pi-night-b` and `pi-night-c`. `harnex lanes` from
    `master` listed all three, and `harnex result` collected each.
  - #92: while the worker ran `sleep 30`, `harnex send` came from a shell
    with no owner id and was delivered as a `follow_up`. The result printed
    `[earlier reply …] TASK REPORT: slept.`, then `[latest reply] BANANA`,
    then `interjected: 1 message … from a terminal (harnex send): "…"`. A
    second `harnex result` printed the same report from the lane record.
    - The first live run found a bug: Pi's `turn_start` before every model
      call cleared the earlier answer. The worker's answer is now kept in its
      own field. The fix went in, was tested and reinstalled, and the step
      was rerun.
  - #91: the worker committed `note.txt` while another commit landed in the
    same checkout during its `sleep 30`. Footer: `1 commit, 1 file (+1 -0)
    (HEAD also moved 1 commit by others)`.
  - #90: with `{"lanes": {"worktree_path": "../lane-{name}", "branch":
    "night/{mm}{dd}_{name}"}}`, `delegate --worktree tpl` worked in
    `../lane-tpl` on `night/1025_tpl`, and `land tpl` merged it into
    `master` and removed the worktree and branch.
  - A second `delegate --name busy` from a sibling worktree, while `busy`
    was working, was refused as the same repo's lane.
  - Every smoke lane was discarded afterwards.
