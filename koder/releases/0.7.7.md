# harnex 0.7.7 — release verification

- **Released:** 2026-06-12
- **Commit:** `c5c23af`
- **Tag:** `v0.7.7`
- **Headline changes:** Codex app-server failed-turn handling fix and Codex schema refresh for `codex-cli 0.139.0`. Failed Codex turns now emit `task_failed`, preserve nested Codex error messages, make `harnex wait --until done` return non-zero, and avoid stale auto-stop `turn/interrupt` after a terminal turn event. Normal structured auto-stop close no longer increments `actual.disconnections`.
- **Verified against:** locally-installed `harnex 0.7.7 (2026-06-12)` via `gem install harnex`.

## Long-run telemetry

No multi-hour or overnight dispatch run was executed for this release. Telemetry validation focused on deterministic failure semantics for a live Codex auth/config failure and a short Pi success smoke. Both installed-binary smokes produced no active registry/tmux residue; structured normal auto-stop close reported `disconnections=0`.

## What this verification did NOT cover

- A successful Codex app-server turn with valid provider credentials; local Codex is currently configured for Azure but `AZURE_OPENAI_API_KEY` is absent.
- Long-running Codex recovery after stream interruption or disconnect-rate fallback (#42 / plan 30 Phases 3–5).
- Pi PTY/TUI marker support (#45).
- Queue-aware telemetry contract implementation (#47) beyond preserving failure/normal-close semantics useful to that work.
- Cross-platform behavior (Linux-only validation in this release).
