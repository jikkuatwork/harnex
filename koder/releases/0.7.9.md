# harnex 0.7.9 — release verification

- **Released:** 2026-07-10
- **Commit:** `7ed0583`
- **Tag:** `v0.7.9`
- **Headline changes:** `harnex run` now supports wrapper-level `--cwd DIR` for public-bundle / temporary-workdir dispatches and `--root DIR` for harnex attribution-only root overrides. `--cwd` starts the wrapped child in the selected directory, uses it as the harnex session root, and defaults dispatch summaries to `<DIR>/.harnex/dispatch.jsonl`, including for non-git directories without raw git fatal noise. Codex schema fixtures were refreshed against `codex-cli 0.144.1` to keep the release suite green with the local Codex CLI.
- **Verified against:** locally-installed `harnex 0.7.9 (2026-07-10)` via `gem install harnex`.

## Long-run telemetry

No multi-hour or overnight dispatch run was executed for this release. Telemetry validation focused on short-lived run-command behavior and terminal summary path/root attribution. The installed smoke used a generic Ruby child rather than launching a real Codex/Pi model turn, so no meaningful token/cost/disconnection metrics were produced.

## What this verification did NOT cover

- Long-running unattended queue monitoring over a real multi-hour worker.
- Visible tmux `--cwd` dispatch inspected by a human; unit coverage exercises tmux command propagation, while installed smoke used foreground generic Ruby.
- Real Codex/Pi model dispatch from a public bundle; installed smoke validated the harnex wrapper with a deterministic Ruby child.
- Security isolation: `--cwd` is a working-directory/root selector, not a sandbox.
- Pi PTY/TUI marker support (#45).
- Typed artifact / validation sidecar ingestion (#52).
- Queue-aware telemetry contract implementation (#47).
- Codex orchestrator recovery (#42) or deployment fallback work (plan 30 Phases 3–5).
- Cross-platform behavior (Linux-only validation in this release).
