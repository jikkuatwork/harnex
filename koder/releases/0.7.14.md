## Long-run telemetry

No multi-hour or overnight dispatch was executed for this release. Verification used the full deterministic suite, short-lived generic Ruby strict-report runs, and a local deterministic Codex app-server stub. The test matrix exercises both Codex `service_tier=flex` and `service_tier=fast` acknowledgment-only metadata paths, but the installed smoke used the default flex path.

No real provider usage/cost sample was generated by the proof-gate smokes. The orchestration smoke used an explicit bounded synthetic primary sample and verified report arithmetic only.

## What this verification did NOT cover

- Real Codex, Pi, or Claude model turns using strict report acceptance.
- Long-running production queue workloads or recovery after a proof failure.
- Live PTY strict-mode prompt transitions in tmux.
- Semantic quality of worker output; Harnex validates activity/report proof shape, not task correctness.
- #57's remaining boot/registration/permission/disconnection outcome classes, correlated failure-family rollup, or process-failure budget command.
- Live app-server recovery/fallback producers for #42 / plan 30 / #43.
- Cross-platform behavior (Linux-only validation).
