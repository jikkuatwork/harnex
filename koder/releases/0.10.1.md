## Live dispatch telemetry

Plan 34 used 17 real Codex app-server dispatches before release: 16 accepted
work outcomes plus one accepted no-change/blocker outcome, no failed terminal
rows, 0 stalls, 0 real disconnections, and 0 force-resumes. This also closes
the real-agent verification gap explicitly left by the 0.10.0 release record.
It was a development/review chain, not a long-run soak.

## Did not cover

- A stress race between `telemetry reconcile --apply` and a simultaneously
  finalizing live dispatch. The implementation re-reads and rechecks under the
  canonical file lock; this release proves deterministic conflict/idempotency
  behavior, not high-contention throughput.
- Very large source trees beyond Holm's current 151 discovered JSON/JSONL files
  and 6.5 MiB / 3563-row canonical stream.
- macOS-specific filesystem behavior. Source discovery avoids symlinks and
  uses Ruby stdlib primitives, but release verification ran on Linux.
- Automatic source cleanup or historical schema migration. Both are deliberate
  non-goals: reconciliation appends only missing rich end rows and leaves source
  disposition to the operator.
- The known cross-process registry stale-field race from 0.10.0 remains outside
  this telemetry-reconciliation slice.
