# harnex 0.30.2 — 2026-11-21

Fixes #99. On the first Mac install (Holm's M4 host), every `harnex ask` and
`wait --timeout` failed with "Operation not permitted" after the worker had answered.

## Verified

- Linux full suite at the release commit `d4473ea` (Holm VM, Ruby 3.3.0): 861 runs,
  4,743 assertions, 0 failures, 0 errors, 1 opt-in Pi skip.
- macOS full suite (M4 host, Ruby 3.3.0): 861 runs, 19 failures, 0 errors; before
  the fix, 21 failures and 6 errors. All 8 that the fix cleared were #99. The 19 left are
  test portability, tracked in #100. No test newly failed.
- The three new tests (Darwin emulated with a stubbed `Process.kill`) were red before the
  fix (`Errno::EPERM`) and green after on both platforms.
- Live, macOS, after `gem install harnex -v 0.30.2` with the locally patched 0.30.1
  uninstalled, Pi 1.6.0: `harnex ask` to `foundry-zyt/gpt-6.2-astra` answered in 6 s
  (exit 0). On 0.30.1 the same ask failed every time.
- Holm VM: `gem install` 0.30.2; `harnex doctor` reports ok, with claude_mcp, pi_mcp and
  gpt_agent integrations present.
- RubyGems `harnex 0.30.2`, tag `v0.30.2`, GitHub `main`; site rebuilt and deployed
  (`holm_app_wQ4TB6JUhrTZ` generation 7; harnex.zyt.app shows v0.30.2). The rebuild
  changed only the version, the changelog and cache-busting hashes.
- `RELEASE_DATE` is current (0.30.1 had left it at 2026-10-25).

## Did not cover

- `delegate --worktree`, `result` and `land` on macOS: only `ask` ran live there.
- The `OwnedProcessGroup` EPERM path live (stopping a Pi worker group on macOS); stubbed
  tests only.
- A live `ask` on Linux with 0.30.2 (doctor only); Linux behaviour is unchanged by design.
- Long-run telemetry: no unattended runs on this release yet.
- The Holm VM still runs Pi 1.5.2. Only the Mac ran `pi update` (1.6.0), because the VM
  was in use.

## Notes

- `bin/gem-push` over non-interactive ssh fails twice: first `otp: command not found`,
  then a 401 once `otp` is on PATH. `~/commands/otp` and `GEM_HOST_API_KEY` load only in
  interactive shells, so run it inside `zsh -ic`.
