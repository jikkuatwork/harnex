# Harnex 0.24.0 — local-only verification

Date: 2026-10-22. Local install only (#87).

## Changes

- The activity snapshot records the current tool's name and the per-turn
  tool count (never arguments). MCP progress lines and `harnex lanes` show
  them.
- Lanes merged by hand are tidied on the next `delegate`, `result` or
  `lanes`.
- Footers:
  - model failures suggest `reply … --model <Pi default>`;
  - lanes with no commits say there's nothing to merge;
  - done lanes say to use `land` rather than `git merge`.
- Evals add S6 (check on a running worker) and S7 (recover from a broken
  model). The exit-124 continuation no longer counts as an error.

## Evidence

- Suite: **815 runs, 4,212 assertions**, 0 failures. Installed `0.24.0`;
  84 files match; both MCP clients connected.
- **Live model failure:**
  - `delegate --model foundry-zyt/gpt-9-imaginary` → FAILED in 4s (404
    model_not_found);
  - `reply bad "Continue…" --model foundry-zyt/gpt-6.1-sol` → resumed the
    session, done in 6s.
- **Agent evals** `~/.cache/harnex-evals/r3-0.24.0` (7 scenarios × 4 routes):
  **26/28 pass, 0 doc lookups on the configured routes.**
  - S4/claude failed because headless `claude -p` stops background work 10
    idle minutes after the main turn. Not harnex: interactive sessions have
    no such ceiling, and `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` lifts it.
  - S6/claude checked on the worker with `tmux capture-pane`; the check's
    regex was too narrow.
  - **Found:** a read-only ask worker used harnex MCP `delegate` to launch a
    writable lane (fixed in 0.25.0).
