[0.30.0] - 2026-10-25 | 02:55 AM | IST

Holm’s first nights with lanes (Holm Queue 167): #89–#92. Published to RubyGems.

Fixed

  • Lane names collided (#89). Identical briefs in sibling worktrees of a bare repo all became pi-read-carry-out-brief, and harnex result NAME then failed with several lanes are named ….
    • A bare layout (repo/.bare plus sibling worktrees) is one repo: its main checkout is the worktree on the bare repo’s HEAD branch, so every worktree shares one lane namespace and harnex lanes shows them all.
    • Generated names skip every name another lane still holds in any repo (working, uncollected, or an unlanded worktree); --name, --worktree and ask --id refuse a name while another repo’s worker runs under it; result/reply find a working lane from anywhere.
    • A lane working in another worktree is named after it (pi-night-1024_s3); brief openers such as “You are a … lane” and “carry out the brief” no longer make the name.
    • delegate --worktree refuses a --cwd that is already another worktree of the repo (it would have branched from the main checkout instead).
  • The gpt agent invented a worktree from brief prose (#89). It now sets worktree, name and cwd only from header lines, takes a new name: header, and passes cwd: on to result and reply.
  • A lane in place reported other people’s commits (#91). Its footer counts only commits that appeared while the worker ran a git command, and names the rest: 0 commits (HEAD also moved 6 commits by others).
  • Messages sent straight to a worker were invisible to the session that started its lane (#92). harnex send now records who sent a message, and a lane’s result lists messages from anyone but the lane’s owner and its own harnex reply (interjected: 1 message … from a terminal (harnex send): "…"). When a message reached the worker after it had answered, the result shows the answers it replaced first, the original task’s report among them.

Added

  • .harnex/config.json lanes templates put worktree lanes where the repo keeps its worktrees (#90): {"lanes": {"worktree_path": "../{name}", "branch": "night/{mm}{dd}_{name}"}} ({name}, {yyyy}, {mm}, {dd}). land and discard follow each lane’s own path and branch.

[0.29.0] - 2026-10-22 | 06:08 PM | IST

The agent release. harnex becomes a tool your coding agents use directly: hand a question or a task to a Pi worker (GPT by default) and get the reply back as plain text, with a footer saying what happened and what to do next. This entry summarizes 0.22.0–0.29.0, the first public release since 0.12.0. Website and docs: https://harnex.zyt.app. Upgrading: docs/upgrading-to-0.29.md.

Highlights

  • Lanes (0.22):
    • harnex delegate [--worktree NAME] hands a task to a worker, optionally in its own git worktree;
    • result collects parallel lanes;
    • reply follows up with the worker’s context (a finished lane resumes its Pi session);
    • land merges and cleans up; discard drops a lane; lanes shows what each worker is doing right now.
  • harnex mcp (0.23): the same verbs as native MCP tools for Claude Code, Pi and any MCP client. Long calls report progress, and Claude Code moves them to the background and notifies on completion. harnex mcp install registers it for both clients.
  • The gpt subagent for Claude Code (0.21, MCP relay since 0.23): ships as agents/gpt.md, and harnex mcp install installs it.
  • Smoothness work (0.24–0.28), measured with evals/agents/run. Real Claude Code and Pi supervisors, with and without MCP, run seven scenarios; 0.28 passed two consecutive full rounds (28/28 each) with no harnex usage errors, no doc lookups and nothing left behind. Along the way:
    • progress detail;
    • the hand-merge sweep;
    • model-failure next steps;
    • forgiving flags and MCP arguments;
    • workers never see harnex’s own MCP tools.

Breaking (since 0.12.0)

  • Codex adapters, the JSON-RPC transport, run --fast/--legacy-pty and preflight --legacy-pty were removed (0.20); harnex is Pi + GPT first.
  • harnex ask waits 9 minutes by default (0.22); use --timeout none for no cap.
  • Pi starts with --no-approve unless -- --approve is passed (0.22).

Added in 0.29.0

  • Docs:
    • docs/lanes.md, docs/mcp.md, docs/agents.md and docs/upgrading-to-0.29.md;
    • GUIDE.md now starts with lanes;
    • TECHNICAL.md gains a “Lanes and MCP” architecture section.
  • The website site/: a monospace, terminal-styled site built from these docs and the live CLI help, deployed as a Holm app to harnex.zyt.app.
  • The gpt agent ships in the gem (agents/gpt.md). harnex mcp install installs it at ~/.claude/agents/gpt.md unless one exists (--no-agent skips it). uninstall removes only an unmodified copy.
  • Gem metadata: a new summary and description, plus documentation and changelog links.

Changed

  • Examples use generic model names (openai/gpt-5.1).

[0.16.0] - 2026-10-18 | 12:55 AM | +04

Owner-authorized local-only release. Owner decision (2026-10-18): Harnex is installed locally and is not published to RubyGems.

Added

  • Final gates: harnex run --final-gate '<cmd>' (repeatable; or meta final_gates) declares final acceptance commands. Receipts gain validation.commands_had_failures (whole-history, harness-observed) and validation.final_gates (declared, observed_pass, observed_fail, missing, status: pass|fail|unknown|undeclared, per-gate last exit). With gates declared, validation.status reports them, so an exploratory or intermediate failure no longer marks a green final run as fail. Matching is exact, after unwrapping a single bash -lc/sh -c transport wrapper. Without gates, behavior is unchanged. Diagnostics only: acceptance and outcome classes do not change (#68).
  • Dispatch-row outcome.class gains process classes from signals Harnex already holds: boot_failure, permission_prompt, timeout, stopped_by_caller, process_failed. They refine an unknown/task_failed terminal or the receipt rejection of a process that never signalled completion; completion and proof verdicts are never overridden, and the vocabulary is closed with an unknown fallback.
  • harnex orchestration report counts worker outcome classes per raw attempt and per retry family (joined by parent attempt/dispatch id), accepts --queue-id as well as --run-id, and takes an optional --failure-budget N [--budget-unit attempts|families] [--fatal-classes A,B] that adds a failure_budget verdict and exits 3 on breach (#57).
  • harnex preflight ADAPTER [--cwd DIR] [--commit-check] runs one tiny real dispatch through harnex run and prints a JSON verdict (harnex.preflight.v1): registration, boot, permission prompt, task read from the task root (default /tmp), workspace write, harness-observed command exit (via a final gate), receipt, worker claims, completion, and stop, plus a scratch-repo commit with --commit-check. Each failure is a distinct check and failure class; a turn that fails before any work reports its (redacted) error as the root cause. Usage, cost and context telemetry provenance is reported per adapter. Exits non-zero on any failed check. Its dispatch row carries phase=preflight (exempt from repo phase allowlists) and orchestration report excludes such rows unless --include-preflight. Workers are stopped through the session API and carry a --max-runtime backstop, so a killed or timed-out preflight cannot orphan them (#56).
  • harnex doctor capabilities add final_gates: 1, outcome_classes: 1 and preflight: 1.

Changed

  • harnex status (default current-repo view) now says how many sessions are active in other repos, with up to three ids, instead of a bare “No active harnex sessions” that read as global emptiness when workers run in sibling worktrees. --repo, --all and --json output is unchanged (#26).
  • A bare harnex wait (process-exit fence) prints a stderr note: when the session was not started with --auto-stop, and again if its turn settles while the wait is blocked, pointing at --until done. Events from an earlier run of the same id are ignored. Status JSON gains auto_stop (#49).
  • Events JSONL ts now has millisecond precision (iso8601(3)), so teardown races can be measured from the events log (#36/#37 follow-up). Readers that parse ISO-8601 are unaffected; older rows keep whole seconds.

Fixed

  • Two status tests that sat below a private keyword never ran; they run now.
  • Test-suite flakes: cross-repo status hint tests no longer see registries leaked by other suites, and the detached on-done smoke waits for teardown.
